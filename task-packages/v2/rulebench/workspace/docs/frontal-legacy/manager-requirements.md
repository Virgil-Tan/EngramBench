【Product Manager】新增 Shadow ComparisonRun。ComparisonRun={comparisonRunId,tenantId,ruleSetId,baselineVersionId,candidateVersionId,evaluationIds,corpusDigest,state:PENDING|RUNNING|COMPLETED|CANCELLED|FAILED,revision,resultCounts:{MATCH,DIFF,ERROR},createdAt,startedAt,completedAt,cancelledAt,promotedAt}。创建时冻结同一 RuleSet 的两个已发布版本，将 1..100,000 个 completed Evaluation ID 去重后按 UUID 升序保存；corpusDigest 是该 ID 数组的 RFC 8785-compatible canonical JSON SHA-256。ComparisonResult={comparisonRunId,evaluationId,ordinal,status:MATCH|DIFF|ERROR,baseline:{decision,tags,explanationDigest}|null,candidate:{decision,tags,explanationDigest}|null,errorCode:string|null,resultDigest}。resultDigest 是除自身外这些字段的 canonical JSON SHA-256。MATCH 表示两侧 decision、tags 和 explanationDigest 全部相同；DIFF 表示两侧均成功但至少一项不同；ERROR 表示任一侧无法产生合法确定性结果，例如排序比较读取到非 safe-integer facts。ERROR 不可由 Worker 或客户端标记为已解释；本版本没有豁免 API，因此只要 resultCounts.ERROR > 0 就禁止 promotion。新增 HTTP 合同：POST /api/v1/comparison-runs，request {tenantId,ruleSetId,baselineVersionId,candidateVersionId,evaluationIds}，response {run:ComparisonRun}；POST /api/v1/comparison-runs/:comparisonRunId/start，request {expectedRevision}，response {run:ComparisonRun}；POST /api/v1/comparison-runs/:comparisonRunId/cancel，request {expectedRevision}，response {run:ComparisonRun}；POST /api/v1/comparison-runs/:comparisonRunId/promote，request {expectedRevision}，response {run:ComparisonRun,ruleSet:RuleSet}；GET /api/v1/comparison-runs/:comparisonRunId，response {run:ComparisonRun,results:[ComparisonResult,...]}。所有 mutation 要求 Idempotency-Key，未知字段仍须拒绝。start 通过 CAS 从 PENDING 进入 RUNNING；cancel 是 durable fence，旧 lease 此后不得提交 Result。Worker 必须读取存储的 facts，分别用冻结版本求值，生成每个 corpus Evaluation 恰好一个不可变 Result，绝不能修改原 Evaluation。completed run 只有在 expectedRevision 匹配且 ERROR 为零时才能 promote；promotion 只把 RuleSet 的 currentPublishedVersionId 指向 candidate 并增加 publicationRevision，绝不修改 RuleSetVersion。状态冲突返回 409 COMPARISON_REVISION_CONFLICT，存在 ERROR 返回 409 COMPARISON_HAS_ERRORS，且两者都无副作用。新增 COMPARISON_EXECUTE Work 和 comparison.started、comparison.completed、comparison.cancelled、comparison.promoted Events；迁移保留所有 V1 版本、解释、回放、幂等结果、lease 与 Event。UI 增加 corpus、进度、diff、cancel 和 promote。正式 comparison-recovery 场景使用 50,000 个 frozen inputs，SIGKILL 两个已 claim Worker，再启动四个 replacement；必须在 60 秒内完成，每个 corpus Evaluation 恰好一个 Result，不能有 digest drift 或重复 Event。本轮只做影响分析和计划。
