Chain 创建时冻结完整步骤：至少两个不同 ACTIVE Carrier，首个 fromCarrierId=Shipment.carrierId，相邻步骤连接，site 沿 ShipmentLeg 单调前进，window 递增且不重叠；一个 Shipment 最多一个非终态 Chain。创建必须原子生成全部 PENDING Handoff、CUSTODY_HANDOFF_EXPIRY Work、Audit 和 Event，任一无效则整批回滚。Handoff 只能按 ordinal 推进；offer 使用数据库时间。accept 由冻结的 toCarrier 的有效 Device 对 custodyHandoffId|carrierId|acceptedAt|expectedChainRevision|keyVersion 做 HMAC-SHA256 attestation，在 window 内原子推进 Handoff、Chain revision/currentOrdinal 和 Shipment Carrier；最后一步完成 Chain。当前 OFFERED Handoff 过期时置 EXPIRED 并取消 Chain，不得推进后续步骤；旧 Carrier、旧 revision、撤销 key、旧 Worker 或旧 lease 不得写。

Recall 按 (tenantId,productLotCode) 原子冻结发布时全部未取消 Shipment；同批次已有非终态 Recall 时拒绝。创建时原子生成 Recall、每个目标 Shipment 的一条 QuarantineAction、RECALL_PROPAGATE/QUARANTINE_ENFORCE Work、Audit、Event 和 NotificationDelivery。quarantine 使用 expectedRevision 从 ISSUED 进入 QUARANTINING；全部 Action APPLIED 后 CONTAINED。APPLIED Shipment 不得 activate、deliver、推进 Chain或被旧 Worker/lease 释放，责任停在最后 ACCEPTED Carrier。取消只允许 ISSUED 且尚无 APPLIED Action 的 Recall；RELEASED 不是取消，本版本没有解除接口。

接口：POST /api/v1/custody-chains，body {tenantId,shipmentId,expectedShipmentState,steps:[{fromCarrierId,toCarrierId,siteId,windowStart,windowEnd}]}，返回 201 CustodyChain；GET /api/v1/custody-chains/:chainId 返回 200 {chain:CustodyChain,handoffs:[CustodyHandoff]}；POST /api/v1/custody-chains/:chainId/handoffs，body {expectedChainRevision}，返回 200 CustodyHandoff；POST /api/v1/custody-handoffs/:handoffId/accept，body {carrierId,deviceId,keyVersion,attestation,acceptedAt,expectedChainRevision}，返回 200 {chain:CustodyChain,handoff:CustodyHandoff,shipment:ColdShipment}；POST /api/v1/recalls，body {tenantId,productLotCode,reason,issuedAt}，返回 201 RecallOrder；GET /api/v1/recalls/:recallId 返回 200 {recall:RecallOrder,actions:[QuarantineAction]}；POST /api/v1/recalls/:recallId/quarantine，body {expectedRevision}，返回 202 RecallOrder。
