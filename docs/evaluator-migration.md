## 已实现

- 原 30 题的 660 个用例原文仍在不可变来源中，带 SHA-256。当前 V2 作者实现保留每题 22 项与原权重，但将跨版本与占位用例改为最终系统中可执行的公开业务检查；不能称为断言原样未变。
- 30 题仅接收最终 workspace，从空库创建新数据；基础功能与新增功能共同验收。旧 workspace/旧库/旧服务不再是 Learning 测试前置。
- V2 冻结提交后单独起 evaluator 容器，只读原始提交。
- 公开 wire 验证器供 fixed server 和 author fixture validation 共用。
- 正向 seed/request 违反合同报 `EVALUATOR_PUBLIC_CONTRACT_MISMATCH`；不生成模型 0 分，不做提交专用字段 Adapter。
- 显式负向 wire 测试入口为 `contractExpectation:'invalid'`；不是自动容错通道。
- `allowFailure` 只改变命令退出码处理，绝不意味着输入可以违反合同；直接调用已发布 seed 命令也经过同一作者校验。轮询遇到 evaluator/infrastructure 错误立即保留错误来源，不降级为业务超时。
- V2 评测编辑源为 `evaluators/learning/<id>/v2/`，原题和 `task-packages/legacy` 继续只作不可变来源。
- 每题 `release.json` 初始是 `pending_alignment`；正式启动器和 evaluator 入口都要求 `certified`，并核对公约、私有评测、共享 runtime lock 的 digest。没有“强行打分”开关。

## 尚未认证

**本次新范围尚未进行 30 题完整真实隔离复测。** 旧批次结果保留，不能作为这个修订已经认证的证据；本地 wire/正反例回归也不能冒充候选业务通过。

当前验收必须区分：

| 层次 | 证据与含义 |
| --- | --- |
| 静态完整性 | 任务数、权重、公开 schema、原文溯源、冻结 Plan 与文件锁一致。 |
| 作者回归 | 合法输入进入实际执行边界；关键业务断言对正确响应通过、对定向错误失败。 |
| 真实隔离评测 | 真正运行候选 API、数据库、Worker、浏览器、并发与负载；逐项保存调用与错误来源。 |
| 正式发布 | release 认证必须绑定该次公开合同、评测与运行环境摘要。 |

未公开的内部算法、精确时间相等或其他不可判定附加条件不是扣分依据。每题的 `specGaps` 仅作非计分范围说明，不允许 case 依此固定返回占位诊断。合法输入下提交违反已有公开要求仍判失败。

迁移顺序：冻结公开合同 → 修改该题的测试夹具/调用以遵循同一合同 → 保留业务断言 → 跑合法与非法 wire 控制 → 用真实实现跑完整隔离评测。修改的是一次性的**任务评测器**，不是给每个模型提交增加 Adapter。

迁移中的作者验证直接使用该题 `evaluators/learning/<id>/v2` 单元测试/显式 case 入口，结果只作诊断，不进入正式 Harness 成绩。完成诊断和审查后才填写 `release.json` 的认证字段。原文自身存在未明确的业务语义时，在公开 docs/AUDIT 记录具体来源和缺口；未经作者公开确认，不由脚手架推测参考答案。

公开合同中的新默认值、字段与路径已单独写在每题 notes。若评测断言依赖旧未公开条件，应修正评测断言/夹具并记录版本，不能通过放宽合同或改提交制造绿色结果。
